# Ein Code Mode

## 실행 경로 선택

작업 단계마다 필요한 도구가 어디에 노출되어 있는지 확인한다. 간단한 조회 한 번이면 호스트가 제공하는 직접 호출을 쓴다. 도구가 셀 안에서만 제공되면 그 경로를 따른다.

1. 여러 호출을 조합할 때는 현재 세션의 네이티브 Code Mode를 우선한다. 예를 들어 Codex의 `functions.exec`에서는 `ALL_TOOLS`와 `tools`, OmO/Senpi의 JS `eval`에서는 `tool_schema()`와 `tool`로 이름과 인수를 확인해 호출한다. 실제 세션에 표시된 명세를 따른다.
2. 네이티브 경로로 처리할 수 없는 단계는 `ein_eval` 같은 폴백이 이미 연결되어 있고, 그 실행기에 필요한 도구가 등록되어 있을 때만 맡긴다. 실행기를 바꿀 때는 필요한 입력을 명시적으로 넘긴다. 권한 거부나 승인 대기는 원래 호스트에서 처리한다.
3. 쓸 수 있는 실행기가 없거나 도구가 호스트에만 있으면 그 도구를 직접 호출한다. 호스트가 병렬 호출을 지원하면 독립 조회를 함께 실행할 수 있다. 스킬 사용을 위해 제품 설정이나 연결을 변경할 필요는 없다.

Codex CLI 세션에서 네이티브 실행기가 보이지 않고 작업에 Code Mode가 유용하면 `codex features list`로 확인한다. 지원되는 `code_mode` 항목의 값이 `false`일 때만 `codex features enable code_mode`를 실행한 뒤 새 세션을 열 수 있다고 한 번 안내한다. 현재 작업은 사용 가능한 도구로 계속한다. 다른 호스트에서는 그 제품에서 확인한 설정 방법만 안내한다.

## 호출 구성과 결과

- 독립적인 읽기와 검색은 한 셀에 모은다. 대상이 많으면 동시 호출 수를 제한하고, 각 결과에 원래 경로나 ID를 붙인다.
- 한 대상의 실패가 나머지 결과를 지우지 않게 수집한다. 예를 들어 JS에서는 `Promise.allSettled`로 모은 뒤, 정상 반환된 응답 안의 도구 오류나 명령 종료 코드도 확인한다. 중간에 멈췄으면 실패한 대상과 아직 시도하지 않은 대상을 구분한다.
- 앞선 결과로 다음 입력을 정하거나 같은 파일·브랜치·레코드를 변경할 때는 순서대로 실행하고 결과를 확인한다. 사용자 확인이 필요한 지점에서는 셀을 끝내고 호스트의 확인 절차를 따른다.
- 필요한 필터링·결합·집계는 셀 안에서 마친다. 예를 들어 여러 설정 파일의 타임아웃을 비교할 때는 경로별 값과 읽기 오류를 반환하고, 읽었지만 키가 없는 파일도 따로 표시한다.
