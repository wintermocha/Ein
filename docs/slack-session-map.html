어느 프로젝트에서 세션을 열까?

메시지 상황 선택

“project:ein 어제 배포 확인해 줘.”

새 스레드에 등록된 프로젝트를 직접 지정

→

코드가 Ein 경로에서 A를 연다

예제의 ein은 설정 파일의 상위 디렉터리(..)에 연결된다. 코드가 이 경로에서 세션을 열고 대화 키와 세션 ID를 기록한다. 실행 자리가 없으면 요청을 대기열에 둔다.

“어제 로그인 오류 좀 봐줘.”

공용 채널에서 웹과 API 모두 후보인 경우

→

메인이 원문과 후보를 보고 판단한다

메인이 스레드의 링크나 앞선 설명에서 근거를 찾으면 프로젝트 ID를 돌려준다. 두 후보가 여전히 가능하면 “웹 로그인인가요, API 인증인가요?”라고 묻는다. 답이 올 때까지 이 대화만 대기한다.

“어제 배포 건만 봐줘.”

Ein 배포 스레드에 후속 메시지가 도착

→

기존 세션 A에서 이어간다

코드가 대화 키로 A를 찾아 후속 메시지를 순서대로 전달한다. 중단된 A는 저장한 세션 ID로 재개한다. 다른 저장소 작업이 추가되면 대화는 A에 두고 오케스트레이터가 해당 프로젝트의 작업 세션을 따로 연결한다.

“온보딩 문서를 고쳐줘.”

문서 프로젝트로 지정한 전용 채널의 새 스레드

→

코드가 문서 경로에서 B를 연다

요청에 다른 대상을 가리키는 단서가 없으면 채널에 등록된 문서 프로젝트를 사용한다. 실행 자리가 있으면 A의 분석과 동시에 B가 작업한다.

“운영 배포 승인도 필요해.”

세션 A의 작업에 승인 절차가 필요

→

A가 판단할 사항만 메인에 보낸다

메인은 원래 스레드에서 소유자에게 승인을 요청할 수 있다. 결정이 돌아오면 A가 같은 스레드에서 이어가고, 관련 없는 세션 B는 계속 진행한다.

대화 기록 · 같은 워크스페이스에서는 채널 ID와 원글 시각(답글의 thread_ts)으로 스레드를 식별한다. 일반 1:1 DM은 DM 채널 ID로 묶는다. 첫 수신 시 대화 기록을 만들고 후속 메시지도 같은 곳에 쌓는다.

실행 위치 · 규칙으로 결정할 수 없는 경우 메인이 등록된 프로젝트 ID를 선택한다. 코드는 ID에 연결된 작업 디렉터리를 확인하고 herdr에서 세션을 연다. 저장소 작업이 필요 없는 질문은 대화에서 바로 답한다.

설정 파일

아인은 시작할 때 JSON을 읽는다. 파일을 바꾼 뒤에는 프로세스를 다시 시작한다. 전체 설정 예제

키허용값·형식기본값·필수 여부언제 어디에 쓰이나
teamSlack 워크스페이스 ID · T…필수연결할 때 봇 토큰의 워크스페이스와 대조하고 대화의 소속을 구분한다.
appIdSlack 앱 ID · A…필수Socket Mode 연결에서 수신한 앱 ID를 대조한다.
botUser봇 사용자 ID · U… 또는 W…필수봇 토큰의 사용자를 대조하고 멘션·자기 글·봇 글에 달린 반응을 구분한다.
ownerUser소유자 ID · U… 또는 W…필수답변 확률에서 소유자를 제외한다. 에이전트로 작업을 요청하거나 확인 질문에 답할 수 있는 사용자를 정한다.
ownerDmDM 채널 ID · D…선택 · 미지정연결 공백을 복구할 때 아직 관찰하지 않은 소유자 DM도 조회한다.
watchChannels채널 ID 배열 · C… 또는 G…필수 · [] 허용채널 멘션을 선별하고 연결 공백 후 조회할 채널을 정한다.
blockedUsers사용자 ID 배열 · U… 또는 W…[]수신 시 사용자 메시지와 반응을 걸러낸다.
otherUserReplyRate채널 ID → 확률 0~1{}해당 채널의 소유자 외 사용자에게 REPLY를 정한다. no면 작업을 만들지 않는다.
appTokenFile앱 토큰을 담은 파일 경로선택 · 미지정라이브 연결을 시작할 때 Socket Mode용 xapp- 토큰을 읽는다.
botTokenFile봇 토큰을 담은 파일 경로선택 · 미지정라이브 연결 시작 시 Web API용 xoxb- 토큰을 읽는다.
stateFileSQLite 파일 경로~/.local/state/ein/inbound.sqlite라이브 시작 시 DB를 열고 수신 위치, 중복 키와 작업 진행 상태를 보존한다.
runneromo | claude | codexorchestrate 필수새 메인·대화·추가 작업 세션에 공통 적용한다. 기존 세션을 재개할 때는 저장한 실행기를 쓴다.
projects프로젝트 ID → 프로젝트 설정선택 · {}등록된 프로젝트만 배정할 수 있다. ID는 영문 소문자로 시작하며 소문자·숫자·밑줄·하이픈으로 최대 64자다. constructor는 사용할 수 없다.
projects.<id>.path작업 디렉터리 경로프로젝트마다 필수시작 시 디렉터리를 확인하고 해당 프로젝트 세션의 작업 위치로 사용한다.
projects.<id>.channels전용 채널 ID 배열 · C… 또는 G…[]새 대화가 도착한 채널로 프로젝트를 찾는다. 같은 채널은 한 프로젝트에만 등록한다.

환경변수 우선순위

EIN_CONFIG가 설정 파일을 지정한다. 생략하면 ~/.config/ein/config.json을 연다. 라이브 모드에서 EIN_APP_TOKEN과 EIN_BOT_TOKEN은 각각 해당 토큰 파일보다 우선하며, 비어 있으면 파일을 읽는다.

경로와 적용 범위

상대적인 EIN_CONFIG는 실행한 위치, JSON 안의 상대 경로는 설정 파일 위치를 기준으로 한다. 절대 경로와 ~/도 지원한다. listen과 replay에는 실행기나 프로젝트 등록이 필요 없다.

구현 파일과 재시작 동작은 구성요소별 구현 문서에서 확인할 수 있다.
